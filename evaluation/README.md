# 检索评测

用固定的分级标注集，在日常素材库的**只读快照**上比较三种检索策略：

- `keyword`：只用元数据，包括文件名、标签、目录、所属模型和集合；
- `semantic`：只用 EmbeddingGemma 2 的向量余弦排序；
- `hybrid`：应用默认的混合检索。

评测不会扫描目录，也不会写入素材库、缩略图或设置。

```bash
npm run test:eval                    # 指标、抽样与合并的单元测试（不加载模型）
npm run eval                         # 评测全部可检索素材 → verification-eval/report.{md,json}
npm run eval -- --only datasets/ prism-material-samples/ --output verification-eval/datasets-only
npm run eval:review                  # 生成抽样复核页 verification-eval/review.html（约 236 张）
npm run eval:merge -- ~/Downloads/prism-review.json   # 合并复核结果并计算一致性
npm run eval:pool                    # 完整复核页：全部标注 + 三种策略 Top-10 中未标注的候选
```

`verification-eval/` 已加入 `.gitignore`。该目录包含本机路径和缩略图链接，不提交到仓库。

## 标注集 `queries.json`

共 118 条查询，669 条非零标注：

| 维度 | 分布 |
|---|---|
| 素材类型 `intent` | 场景 27、插画 33、材质 16、道具 15、UI 9、3D 模型 8、截图 5、其他 5 |
| 语言 `lang` | 中文 102、英文 16（其中 12 条与中文查询同义，可直接对照中英文效果） |
| 方式 `style` | 画面描述 109、名称 7、名称加描述 2 |

- 标注以**相对关联目录的路径**为键，素材重新索引后 ID 会变，但路径不变，标注仍然有效。
- 评分分四级：3 为完全符合，2 为高度相关，1 为部分相关，0 为不相关。
  显式写出的 0 表示“看过、判定不相关”；未写出的素材同样按 0 计分。
- 完全重复的文件（SHA-256 相同）在检索中会被聚合成一个结果，评测时取组内最高分。
- Recall 和 MRR 把 2 分及以上算作相关；nDCG 使用分级增益 `2^g − 1`。
- Recall 和 nDCG 的分母是“当前检索范围内能找到的已标注素材”，范围外的标注不计入。

### 标注来源与局限

1. 初稿：逐张查看素材库缩略图后标注。
2. 补标（pooling）：把三种策略的 Top-10 合并成候选池，对池中未标注的素材补打分数。

因此，三种策略 Top-10 以外的相关素材可能有遗漏，Recall 会偏高。人物立绘类查询（如“海滩”“体育运动”）的边界比较主观。初稿由 AI 辅助完成，补标池里判定不相关的 691 张已写为显式 0。

### 人工复核：抽样，而不是逐张

不需要复核全部 1,360 条标注，只需验证 AI 初稿是否可信。

1. 运行 `npm run eval:review`，生成 `review.html`。
   - 每条查询抽 2 张，共约 236 张，大约 10–15 分钟。
   - 抽样按分数分层，0、1、2、3 分（包括“看过、判定不相关”的显式 0）的抽中次数大致相当。
2. 双击 `review.html` 打开。缩略图已内嵌在页面中，不依赖本机其他目录。
   - 初稿分数一开始隐藏，避免被初稿影响。
   - 点击第一张卡片后按 `0`–`3` 打分，会自动跳到下一张。
   - 打完分后，与初稿不同的卡片会显示“初稿 N 分”。
3. 点击“导出复核结果”，得到 `prism-review.json`。
4. 运行 `npm run eval:merge -- ~/Downloads/prism-review.json`。
   - 你的分数会覆盖初稿。
   - 同时计算一致性：完全一致率、相差 ≤1 分的比例、加权 Cohen's κ，以及按“≥2 分为相关”计算的 κ。
   - 结果累计记录在 `queries.json` 的 `audits` 中，之后 `npm run eval` 生成的报告会自动写入这些数字。

再跑一次 `eval:review` 会换一个随机种子，抽到另一批，可以继续扩大样本。

一般认为加权 κ ≥ 0.8 是高度一致。如果一致率低，可以看 `merge` 输出的 `changes`，找出 AI 初稿系统性偏高或偏低的查询类型，再用 `npm run eval:pool` 打开完整复核页，只修改那几类查询。

索引模型或预处理改变时，`PROFILE` 会变化，评测脚本会拒绝运行，需要先在应用中完成重建索引。

## 当前结果（2026-11-01，Apple M5 / 16GB）

### 日常库全部可检索素材（446 个文件，118 条查询）

| 策略 | MRR | Recall@10 | nDCG@10 |
|---|---:|---:|---:|
| keyword | 0.076 | 0.041 | 0.053 |
| semantic | 0.775 | 0.817 | 0.758 |
| hybrid | **0.834** | **0.847** | **0.799** |

### 仅 `datasets/` 与材质样本（369 个文件，109 条查询）

| 策略 | MRR | Recall@10 | nDCG@10 |
|---|---:|---:|---:|
| keyword | 0.083 | 0.066 | 0.074 |
| semantic | 0.891 | 0.941 | 0.871 |
| hybrid | **0.927** | **0.962** | **0.905** |

配对自助法（按查询重采样 10000 次）：

- hybrid 比 semantic 的 nDCG@10 高 +0.041，95% 区间 [+0.015, +0.072]；9 条查询提升，0 条下降。
- 只在 `datasets/` 范围内为 +0.034，95% 区间 [+0.008, +0.067]。

### 结论

1. **语义检索是主力**。描述画面的查询占 109 条，在这类查询上 keyword 几乎无效（nDCG@10 为 0.006），因为 ArtStation 图片和卡面的文件名都是随机 ID。
2. **混合检索的收益集中在关键词能命中的查询上**。共 9 条查询有提升，其中 7 条是名称类查询（如“丽芙”“木地板”），另外 2 条是“锈蚀金属”和“rusty metal material”，它们命中了材质资产的名称。在名称类查询上，semantic 的 nDCG@10 只有 0.24，hybrid 达到 0.86；其余 109 条查询中，hybrid 与 semantic 的结果完全相同。说明严格分级的混合排序没有拖累语义检索，但也只在关键词命中时才起作用。
3. **界面截图形成了“枢纽干扰”**。整库评测中，`search-loading-light.png` 在 66 条无关查询里进入了 Top-10，`01-empty.png` 进入了 50 条。这类低信息量的界面截图与几乎所有文字查询都有较高的余弦相似度。把检索范围限定到 `datasets/` 后，semantic 的 nDCG@10 从 0.758 升到 0.871。这说明在库里排除开发截图目录，能直接改善检索效果；在模型层面也可以考虑做 hubness 校正。
4. **多词关键词查询要求每个词都命中**。“丽芙 3D模型”中的“3D模型”没有出现在任何元数据字段里，所以 keyword 返回 0 条；hybrid 因此退回纯语义排序，nDCG@10 降到 0.19（整库）。可以考虑放宽为部分词命中，或者把“模型”“贴图”这类类型词识别为筛选条件。
5. **当前较弱的查询类型**：材质类整库 nDCG@10 为 0.65，PBR 编辑器截图会抢占排名；另外“黑暗洞穴里的火光”“神社参道”“哥特风黑色洋装”这类以氛围或服饰细节为主的查询也较弱。
